# v0.1.8 — The guard that caught itself

*Released 2026-08-31*

v0.1.7 shipped a check that runs the freshly-built binary and refuses to
release if it can't say its own version out loud. Twenty seconds later that
check failed the v0.1.7 release. It was right to fail — just about the wrong
thing. GoReleaser hands the build a version with the `v` filed off, so the
binary proudly announced `git-release 0.1.7` while the check stood there
holding a card reading `v0.1.7` and shaking its head.

Which is, in fairness, exactly the behaviour you want from a guard on its first
day: loud, wrong in a way you can read off the log in one glance, and fixed in
two minutes. It also incidentally proved the thing everyone actually cared
about — that same log line shows a real version and a real commit hash, where
five months of releases had only ever managed `dev (commit: none)`.

So v0.1.8 teaches the check to strip the `v` before comparing. It is a
six-line diff and the least interesting release this tool has ever had, which
is the point: it exists so the release pipeline's last run is green and the
next person to look at it believes what it says.
